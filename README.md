# Evidence-Aware Baseband CVE Dataset

This repository contains the source-only, schema-3.1 reproduction pipeline. Its
Nix flake pins both the execution environment and the official CVE List V5 Git
revision. No acquired JSON or generated datasets are stored in Git.

## Reproduce

From the repository root, run:

```bash
nix --extra-experimental-features 'nix-command flakes' run .
```

The default app performs both stages automatically:

1. `fetch_json.py` scans the pinned CVE List V5 checkout offline and writes the
   four vendor collections to `fetched_json/`.
2. `enrich.py` reads those fresh collections plus `cve_table.typ` and writes the
   datasets, source-provenance metadata, manifest, CSV, and figures to `outputs/`.

During the bulk scan it prints progress every 25,000 CVE records, including
elapsed time, candidate count, and records per second.

Both generated directories are ignored by Git. Pass enrichment arguments after
`--`, for example:

```bash
nix --extra-experimental-features 'nix-command flakes' run . -- \
  --output regenerated --no-plots
```

Set `BASEBAND_CVE_FETCH_DIR` to place the intermediate vendor JSON elsewhere.
The default is `$PWD/fetched_json`.

## Explore in the browser

Run the bundled Baseband Memory Safety Bugs Overview frontend against the
currently generated data in `outputs/` with:

```bash
nix --extra-experimental-features 'nix-command flakes' run .#website
```

This target only starts the website; it does not fetch, enrich, plot, or verify
data. Generate fresh artifacts and start the frontend in one command with:

```bash
nix --extra-experimental-features 'nix-command flakes' run .#site
```

Then open <http://127.0.0.1:8000>. The website reads only the JSON generated by
this repository. It makes no external API requests and uses no CDN assets.
Choose another listener with `-- --host 0.0.0.0 --port 8080`. Set
`BASEBAND_CVE_OUTPUT_DIR` or `BASEBAND_CVE_FETCH_DIR` to relocate generated
files.

## Repository contents

```text
.
├── flake.nix          # environment and fetch → enrich default app
├── flake.lock         # pinned Nixpkgs and cvelistV5.git revisions
├── fetch_json.py      # deterministic CVE List V5 acquisition
├── enrich.py          # classification, exports, provenance, and figures
├── verify_outputs.py  # independent integrity and frozen-result checks
├── serve.py           # local static/data server
├── web/               # Baseband memory-safety artifact explorer
├── cve_table.typ      # manually reviewed enrichment annotations
└── README.md
```

The flake also exposes individual `fetch`, `enrich`, `serve`, `website`, and
`site` apps. Inside `nix develop`, `$CVELISTV5_DIR` points to the immutable CVE
List checkout.

## Expected result

The pinned input and manual annotations yield 622 unique CVEs. The policy keeps
447 memory-safety records and excludes 175 records: 134 matched non-memory rules
and 41 identifier-specific manual exclusions for non-baseband or non-memory
cases. The retained impacts are:

- 11 RCE;
- 170 write primitive; and
- 266 denial of service.

CVE-2022-21744 is classified as RCE with public exploitation evidence. Its root-cause source is the TASZK PNCD
post, and its execution evidence is TASZK's Full Chain Baseband Exploits, Part 2.

Evidence depth uses three bands: advisory only; technical characterization
(reproduction, detailed root cause, or memory-primitive analysis); and
exploitation evidence (control-flow redirection or confirmed code execution).
The website communicates these bands with row colors and plain-language
descriptions, while retaining the underlying evidence flags in the JSON.

The acquisition phase intentionally uses only the locked CVE repository during
default reproduction. Live Android and vendor-site crawling remains available
through the separate `.#fetch` app for discovery work, but does not affect the
reproducible default dataset.
